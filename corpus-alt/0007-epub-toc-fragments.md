## 背景

ADR-0006 は目次を平坦なリストで返し、フラグメント（`#fragment`）を落とすと
決めた。理由は `href` を本文の章と一致させ、UI が突き合わせられるように
するためだった。

一方で、実際の EPUB には `ch.xhtml#section-3` のように文書内の位置を指す
目次項目がある。リーダーの「目次・ページ・章を移動できる」検証条件には
章内の位置への移動が含まれる。`href` の一致規則はそのままに、位置の情報を
失わない必要がある。

また、フラグメントのみの `href`（`#...`）や空の `href` は、ADR-0006 の
実装では `CoreError::Archive` となり、目次全体が読めなくなっていた。
1 件の不正な項目で目次全体を失うのは実用上脆い。

## 決定

`EpubTocEntry` に `fragment: Option<String>` を追加する
（`title`・`href`・`fragment`・`depth` の順）。

- `fragment` は生の `href` / `src` の最初の `#` の後ろ。`#` を除き、前後の
  空白を除去したもの。空なら `None`。
- パーセントエンコードは復号せず、元の綴りのまま保持する。2 個目以降の
  `#` は区切りにしない（`#a#b` のフラグメントは `a#b`）。
- `href` は従来どおりフラグメントを含まない（章との一致規則を変えない）。
- パス部が空の `href`（属性なし・空文字列・空白のみ・フラグメントのみ）は
  エントリにせず読み飛ばす。エラーにはしない。
- 分割規則は 1 つのヘルパー（`split_fragment`）に置き、nav と NCX で
  共有する。
- `resolve_href` は変更しない。manifest の検証は従来どおり。

## 選択肢と根拠

| 選択肢 | 判断 |
| --- | --- |
| `fragment` を別フィールドで保持し、復号しない（採用） | 元の綴りを保ち、不正な `%XX` の復号ポリシーを持ち込まない |
| `href` にフラグメントを含めて返す | ADR-0006 の「章と突き合わせる」性質を壊す。UI の対応付けが複雑になる |
| 復号済みのアンカー名を返す | DOM 照合の実装時に必要になったら追加できる。今は消費側が解釈する |
| 空パスの `href` をエラーとして扱い続ける | 1 件の不正で目次全体が使えなくなる。スキップして残りを活かす |
| `playOrder` や `landmarks` の再検討 | 今後の課題。本決定の範囲外 |

## 影響

- UI は `toc()[i].href` で章と対応付け、`toc()[i].fragment` で章内の位置へ
  移動できる（例: ハッシュとして設定し、ブラウザにスクロールさせる）。
- `EpubTocEntry` はフィールド追加のみの変更。公開 API の破壊的変更はない
  （pre-1.0 のため、構造体リテラルの構築箇所は要素追加が必要）。
- 空パスの `href` は `CoreError::Archive` から「読み飛ばし」へ変わる。
  nav / NCX の解析のみで、manifest の検証は変わらない。
- エントリ数の上限（10000）と `depth` の規則は変わらない。読み飛ばした
  項目は数えない。

- 外部クレート視点の受け入れテスト 5 件を一時作成し、すべて pass したのち

## 解決済み

- アンカーへの実際の移動: ADR-0046 で位置適用を実装。
- 章内リンクのアンカー利用: ADR-0055 で同一章フラグメント移動を履歴に記録。
- `fragment` の復号: core の OPF / nav 解析で `%XX` を復号済み。
- `landmarks` / `page-list`: ADR-0027 / 0028 で UI を実装。
